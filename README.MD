# Запуск автоматизированных тестов

## Описание

Данный проект содержит автоматизированные тесты для Java-приложения, разработанные в рамках [тестового задания](/task-description/README.md).

## Требования

Для запуска тестов необходимы:

- **Java 17** или выше
- **Gradle 9.8** или выше
- **Docker** — для запуска тестируемого приложения в контейнере

## Запуск тестов

### 1. Запуск с локально развернутым приложением

Если тестируемое приложение уже запущено на вашей машине, необходимо настроить подключение к нему.

Откройте класс `Base` и найдите метод `createRequestSpecification()`.

В этом методе:

1. В `baseUrl` укажите URL тестируемого приложения.
2. В `.header("X-Api-Key", "****")` замените `****` на значение API-ключа (`secret`), используемого при запуске приложения.

После настройки выполните команду:
```
./gradlew test
```

### 2. Запуск с использованием Docker

Если тестируемое приложение не развернуто локально, но установлен и запущен Docker, тесты можно выполнить с использованием контейнеризированного окружения.

Для этого выполните команду:
```
./gradlew test -PwithDocker=true
```

Параметр `withDocker=true` активирует запуск тестов с использованием Docker.

## Примечание по безопасности

В текущей реализации API-ключ (`secret`) задается непосредственно в исходном коде.

**Это временное решение, которое требует доработки.** Хранение секретных ключей в исходном коде не соответствует рекомендуемым практикам безопасности.

В дальнейшем необходимо реализовать передачу API-ключа через переменные окружения или другой безопасный механизм конфигурации, исключающий хранение секретов в репозитории.

## Известные проблемы

### Несоответствие валидации токена требованиям

На текущий момент часть автоматизированных тестов завершается с ошибкой
из-за несоответствия текущей реализации приложения требованиям,
описанным в тестовом задании.

**Ожидаемое поведение:**
Согласно документации, токен должен состоять из 32 символов,
включая заглавные латинские буквы от A до Z и цифры от 0 до 9.

Регулярное выражение: `[A-Z0-9]{32}`

**Фактическое поведение:**
Текущая реализация приложения принимает только символы
от A до F и цифры от 0 до 9.

Регулярное выражение: `[A-F0-9]{32}`

**Влияние на тестирование:**
Тесты, проверяющие использование допустимых символов
из диапазона G-Z, не проходят, поскольку приложение
отклоняет такие токены.

Тесты намеренно сохраняют проверки согласно документации,
чтобы зафиксировать обнаруженное несоответствие.

После исправления валидации токена необходимо повторно
запустить тесты и убедиться в соответствии реализации требованиям.
